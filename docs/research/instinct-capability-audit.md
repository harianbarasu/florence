# Instinct/Poke capability audit for Florence

Research date: 2026-08-28

## Decision

Florence is no longer merely a Google-search bot. It already has a useful read-and-reason layer. The competitive gap is **finishing ordinary family work across services**.

Instinct describes an assistant that uses email, messaging, screen, audio, location, a phone, and a computer; follows up on dropped threads; and produces outcomes such as an airport ride or a booked handyman. ([Instinct product page](https://instinct.co/)) Poke makes the execution surface more concrete: email sends and organization, multi-calendar scheduling, reminders, real-time background automations, custom MCP tools, browser-backed reservations, travel automations, and optional human completion for calls, orders, rides, and reservations. ([Poke product page](https://poke.com/), [Poke integrations docs](https://poke.com/docs/managing-integrations), [Poke release notes](https://poke.com/docs/release-notes), [restaurant-reservation recipe](https://poke.com/r/restaurant-reservations))

The next work should therefore extend Florence's existing durable family-work loop with real action tools. It should not add another abstract agent framework, a generic connector marketplace, or coding tools.

## Next concrete tools, in priority order

1. **Email and contacts:** `gmail_draft`, `gmail_reply`, `gmail_send`, `gmail_forward`, `gmail_label`, and `contacts_search`. Put them inside durable family work so “email the camp and let me know” can send, wait for a reply, and close the loop.
2. **Authenticated browser completion:** `browser_open`, `browser_read`, `browser_click`, `browser_type`, `browser_select`, `browser_upload`, and `browser_submit`, with task-scoped continuation state and a final external receipt. First jobs: school forms/portals, restaurant reservations, appointment booking, and subscription cancellation.
3. **Travel state, not just flight search:** `flight_status` by flight number/date, `trip_extract` from confirmations, `travel_monitor`, hotel search, and ground-transport options/booking. A flight identifier should resolve route/status without another question.
4. **Local service coordination:** richer `place_details` (hours, phone, site, booking surface), `contact_provider`, quote/reply tracking, `reserve_restaurant`, and `book_ride`. Later, add a human-completion fallback only for jobs automation repeatedly cannot finish.
5. **Google Workspace documents and tasks:** `drive_search/read`, `docs_read/create/update`, `sheets_read/update`, and `tasks_create/update/complete`. This turns school PDFs, rosters, forms, and plans into actions instead of summaries.
6. **Commerce and account chores:** product/service comparison, price and availability monitoring, cart/order actions, subscription discovery/cancellation, and receipt tracking. Reuse the browser completion tool where a dedicated provider action is unnecessary.
7. **Selected household connectors:** TripIt/Flighty, Todoist, Notion, and a small number of high-frequency family services. Extend the current typed capability catalog directly; do not build a Poke-style marketplace before these connectors are real.
8. **Calls:** live parent-to-Florence voice and outbound provider calls. Instinct makes calling part of the core interface; for Florence the first practical win is calling camps, doctors, restaurants, and service providers while keeping the result in the family thread. ([Instinct](https://instinct.co/))

## Product acceptance bar

A new tool counts only when a parent can state an ordinary objective in Messages, Florence acknowledges immediately, derives public details instead of asking for them again, continues through more than one step when needed, reports a genuine blocker only when one remains, and ends with a useful result or honest failure. Search results and promises to work later do not count as completion.
